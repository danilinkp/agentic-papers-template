# Шаблон НИР и курсовых с Codex

Проект объединяет рукопись LaTeX, журнал исследования, проектный MCP и плагин с навыками Codex. Для каждой работы создавайте отдельную копию шаблона и выбирайте профиль в [паспорте работы](research/brief.md).

## Первый запуск

```sh
make setup-codex
make pdf
```

Для MCP нужен Python 3.9+. В VS Code откройте папку проекта с расширением LaTeX Workshop. [Настройки проекта](.vscode/settings.json) повторяют пользовательский рецепт `latexmk (pdflatex)` и добавляют SyncTeX и раздельные каталоги результатов. VS Code вызывает уже доступные в PATH `latexmk`, `pdflatex` и `bibtex`. Пакеты для оформления перечислены в [преамбуле](docs/preamble.tex).

Откройте точку входа нужного профиля и выполните `LaTeX Workshop: Build LaTeX project`. Откройте результат через `LaTeX Workshop: View LaTeX PDF`. Из общего файла, например `metadata.tex`, для явного выбора профиля переключитесь на нужную точку входа. Настройки конкретной работы находятся в проекте. [LaTeX Workshop](https://github.com/James-Yu/LaTeX-Workshop/wiki/Compile)

| Профиль | Точка входа | PDF из VS Code | Проверка в терминале |
|---|---|---|---|
| НИР | [docs/main.tex](docs/main.tex) | `build/vscode/main/main.pdf` | `make nir` → `build/nir/main.pdf` |
| Курсовая | [docs/coursework.tex](docs/coursework.tex) | `build/vscode/coursework/coursework.pdf` | `make coursework` → `build/coursework/coursework.pdf` |

Запустите настройку в обычном терминале с доступом на запись в проект. Откройте корень проекта в Codex, подтвердите доверие к проекту и начните новую сессию. В CLI наличие MCP проверяется командой `/mcp` в интерактивной сессии. Для новой установки найдите и установите локальный плагин через `/plugins` или каталог плагинов приложения, в источнике «Шаблон научных работ». Для проверки MCP попросите разрешить DOI `10.1093/comjnl/27.2.97` через `academic_literature`.

Команда настройки создаёт `.codex/config.toml`, файлы ролей в `.codex/agents/` и локальный каталог в `.agents/plugins/`. Версионируемые исходники находятся в [codex/setup](codex/setup/). Команду можно повторять в одной копии. При конфликте с существующими файлами скрипт укажет, что нужно объединить вручную.

## Рабочий процесс

| Навык | Что поручить Codex | Где хранится результат |
|---|---|---|
| `research-paper-writing` | Вести работу от постановки задачи до финальной рецензии | Паспорт, журналы, оформленная рукопись и PDF |
| `plan-study` | Вывести цель, задачи и план проверки из темы и методички | [Паспорт работы](research/brief.md) |
| `find-literature` | Найти работы, сверить метаданные и зафиксировать основания для тезисов | [Журнал поиска](research/sources.md), [библиография](docs/bibliography.bib) |
| `write-paper` | Написать или отредактировать раздел и собрать PDF | [docs/sections/](docs/sections/) |
| `review-paper` | Сверить выводы с задачами, ссылками, экспериментами и итоговым PDF | Замечания с указанием мест в рукописи |

Пример первого запроса в Codex.

> Используй навык plan-study. Прочитай методичку в проекте, заполни паспорт НИР и предложи план обзора. Для каждой задачи укажи, какой результат её закроет. Запиши вопросы, которые нужно согласовать с руководителем.

Для поиска и рецензирования можно явно попросить Codex вызвать роли `literature-researcher` и `paper-reviewer`. Основной агент принимает их результаты и сводит правки рукописи. Для собственных измерений сохраняйте исходные данные, команды и версии в [журнале экспериментов](research/experiments.md).

## Инструменты исследования

| Инструмент | Для чего и как доступен |
|---|---|
| `academic_literature` | Включён. `crossref_search` и `crossref_lookup` ищут метаданные, `arxiv_search` ищет препринты. [Crossref](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) · [arXiv](https://info.arxiv.org/help/api/user-manual.html) |
| Проверка ссылок | `verify_citation` сопоставляет DOI с заглавием и, при наличии, фамилией первого автора и годом. Совпадение означает сверку метаданных Crossref. Цитаты, номера страниц и детали алгоритма проверяйте по полному тексту. DOI вне Crossref проверяйте у издателя или регистратора. |
| Zotero | `zotero_search` и `zotero_export_bibtex` читают личную библиотеку Zotero Desktop. Запустите Zotero и включите доступ другим локальным приложениям в расширенных настройках. Ключ Zotero Web API не нужен. При импорте сохраняйте существующие ключи библиографии. [Zotero Local API](https://www.zotero.org/support/dev/web_api/v3/local_api) |
| Чтение PDF | `pdf_info` показывает число страниц, `pdf_read_pages` извлекает текст, `pdf_render_page` возвращает изображение страницы для проверки таблиц, формул, сканов и графиков. Нужны утилиты Poppler. Положите PDF внутрь проекта, например в `.local/papers/`. Номера инструментов соответствуют порядку страниц в PDF. |
| Context7 | Включён. Ищет документацию по языкам, библиотекам и технологиям. Указывайте версию и открывайте официальный источник для цитирования. Публичный endpoint работает без ключа. Для повышенных лимитов настройте `CONTEXT7_API_KEY` через окружение и `env_http_headers`. [Context7 для Codex](https://context7.com/docs/clients/codex) |
| Playwright | Опциональный браузер для страниц издателей и документации. В проектном `.codex/config.toml` установите `enabled = true` в `mcp_servers.playwright`. Нужны Node.js с `npx` и Google Chrome. Браузер запускается headless с отдельным временным профилем. [Playwright MCP](https://github.com/microsoft/playwright-mcp) |
| Google Scholar | Опциональный дополнительный поиск. Подключение и ограничения описаны ниже. |

### Google Scholar MCP

Проверенный репозиторий предоставляет поиск по ключевым словам, фильтрацию по автору и годам и поиск профилей исследователей. Поиск разбирает HTML выдачи. Поле `Abstract` содержит сниппет, а HTTP-ошибки могут возвращаться как пустая выдача. Даже ответ HTTP 200 может дать пустой список, если структура HTML отличается от ожидаемой. Используйте сервис для поиска кандидатов и проверяйте найденные работы по первоисточникам. [Репозиторий и исходники](https://github.com/JackKuo666/Google-Scholar-MCP-Server/tree/738d60a4d69464731e7c5b3a61767c06ff2cec0d)

Для подключения в отдельной копии проекта нужен `uv`. Из корня проекта выполните:

```sh
git clone https://github.com/JackKuo666/Google-Scholar-MCP-Server.git .local/google-scholar-mcp
git -C .local/google-scholar-mcp checkout --detach 738d60a4d69464731e7c5b3a61767c06ff2cec0d
```

Затем поставьте `enabled = true` у `mcp_servers.google_scholar` в `.codex/config.toml` и откройте новую сессию Codex. Первый запуск подготавливает окружение Python для сервера. В конфигурации зафиксированы совместимые версии MCP SDK и bibtexparser. Локальный запуск возвращает ошибку HTTP через MCP, чтобы она не выглядела как отсутствие публикаций.

При недоступности MCP используйте поиск Codex, каталоги издателей и предоставленные статьи. Для ручного подключения навыков скопируйте `plugins/paper-workbench/skills/` в `.agents/skills/` и отключите локальный плагин в `.codex/config.toml`, чтобы избежать дублирования.

[Настройка MCP](https://developers.openai.com/codex/mcp) · [Локальные плагины](https://developers.openai.com/plugins/build/plugins#install-a-local-plugin-manually) · [Навыки](https://developers.openai.com/codex/skills) · [Роли агентов](https://learn.chatgpt.com/docs/agent-configuration/subagents#custom-agents)

## Адаптация LaTeX

- Отредактируйте [метаданные](docs/metadata.tex) и паспорт, затем заполните общие разделы и разделы выбранного профиля. Удалите демонстрационную ссылку и запись `knuth1984`, когда добавите свои источники.
- [Преамбула](docs/preamble.tex) и [стиль библиографии](docs/modified-utf8gost705u.bst) перенесены из курсовой по БД. Сохранены поля, шрифты основной части, оформление оглавления, подписи, нумерация рисунков, таблиц и листингов по разделам и нумерация в приложениях буквами. Курсовая повторяет четыре основных раздела образца. Для НИР используется структура «обзор — методы — результаты и обсуждение».
- [Редактируемый титул](docs/titlepage.tex) воспроизводит компоновку образца с эмблемой и полями подписей. Он набирается шрифтами LaTeX. Чтобы сохранить начертание и вёрстку утверждённого титула, положите PDF в `docs/` и задайте `\paperFrontmatterPDF` в метаданных. По умолчанию вставляются все страницы. Для режима как в итоговом PDF курсовой задайте `\paperFrontmatterPages` равным `1` и `\paperFirstPage` равным `4`. В курсовой включён перечень сокращений. При необходимости задайте `\paperAbbreviationsfalse` или включите приложения через `\paperAppendixtrue`.
- В [библиографии](docs/bibliography.bib) используйте поля BibTeX, которые читает стиль образца. Например, `journal` для журнала, `language = {english}` для англоязычной записи, `url = {\url{...}}` для URL и `accessed` для даты обращения. DOI можно указать ссылкой `https://doi.org/…` в поле `url`. Если после перехода с Biber остались старые вспомогательные файлы, переместите каталоги `build/nir` и `build/coursework` и повторите `make pdf`.

Чтобы добавить ещё один профиль, создайте точку входа по образцу [coursework.tex](docs/coursework.tex), план разделов в `docs/sections/<профиль>/plan.tex` и цель в [Makefile](Makefile). Для новых навыков добавьте каталог с `SKILL.md` в [плагин](plugins/paper-workbench/skills/). Настройки дополнительных MCP храните в [исходной проектной конфигурации](codex/setup/config.toml).
